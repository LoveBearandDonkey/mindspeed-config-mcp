### 需要保留的解析差异

页面 YAML 明示微批 `1`、全局批 `12288`、EP 从 DP 内切出、CP=Ulysses；当前解析器把 `runner_config.batch_size=12288` 放入 `batch.micro_batch_size`，并将 `ep_mode` / `cp_mode` 填成 `mf` / `ring`，这些是**解析映射差异**，不得写成原始配置错误。契约副本的 `pipeline_layer_offsets` 已映射，原先由缺失映射导致的“均匀 PP 保底”候选已经消失。契约副本同时保留了两个不同的模型名称字段，解析器目前提示覆盖差异；需要核对其 MindFormers 语义，不能当成训练阻断。

Phi‑4 脚本默认 `MODE` 由第一个命令行参数决定；本轮内嵌 JSON 快照明确选择 `superoffload`、批量默认 `4`。若用户实际运行 `zerooffload` 或传入其他批量，必须重新读取对应生成结果，旧结论不能沿用。当前解析器把 ZeRO‑3 映射为 `fsdp2`，这只是其通用分片归一化口径，不足以验证 DeepSpeed SuperOffload 的 CPU 比例、pin memory、CPUAdam 线程或实际设备兼容性。

两组的场景 2、3 若后续要落实候选，仅在原件副本上修改；必须展示差异、重新读盘并调用修改复查。容量结果只按工具的 `theoretical` 标记，真实峰值和吞吐留给目标环境实测。
