# 页面原型拷贝清单

本文说明从仍在更新的 `compute-graph-viewer-wzh` 中，哪些文件适合拷贝到
`mindspeed-config-mcp` 继续开发。当前只做清单和边界确认，**尚未执行拷贝，也不会
修改原仓库**。

## 建议结论

**第一版 MCP 不拷贝页面文件。**

下面两份文件是产品介绍和导航门户，不参与 MCP Tool 的注册、输入校验、Rank 计算、
修复建议或容量估算：

1. `Profiling_Insight_and_Tool/training-run-twin-standalone/mindspeed-tool-matrix-analysis.html`
2. `Profiling_Insight_and_Tool/training-run-twin-standalone/mindspeed-agent-overview.html`

只有以后明确要随 MCP 一起提供演示门户时，才考虑把它们放到：

```text
apps/web/prototype/
  mindspeed-tool-matrix-analysis.html
  mindspeed-agent-overview.html
```

这两份页面的样式和脚本都写在 HTML 内部，互相通过相对链接切换，适合作为可选的
演示资产；但它们不是 MCP 的运行时依赖，也不会强化 Agent 的分析能力。当前继续留在
原产品仓库即可。

## 不建议整页拷贝

暂不拷贝 `config-relation-plane.html`。它不是一个真正自包含的页面，会继续依赖多套
CSS、页面控制器、导入器、YAML 生成器和可视化脚本；仅主要 HTML 与 JavaScript
文件就超过 1 MiB。整套搬运会产生第二份难以同步的产品代码。

第一版 MCP 需要的左侧“训练配置”信息，已经用以下形式在本项目内固化：

- `packages/contracts/training-config-v1.schema.json`：稳定输入契约；
- `packages/config-core/`：配置校验、Rank 拓扑、修复建议和理论容量估算；
- `tests/fixtures/`：标准化输入样例；
- `tests/golden/`：A01～A15 交互验收结果及动态 PP Stage 边界；
- `tests/compatibility/page-rules.test.js`：在旧仓库可用时进行只读规则兼容检查。

因此，新项目的页面应直接消费 `config-core` 的结构化结果，不再复制
`config-relation-observer.js`、`config-relation-plane.js` 或
`config-relation-capacity.js` 的 DOM 与绘图实现。

## 仅作只读对照的文件

以下文件不进入新项目运行包，只在规则升级或回归检查时读取：

| 原文件 | 用途 | 处理方式 |
| --- | --- | --- |
| `shared/plane-rules.js` | EP、world size、DP/EDP 和 Stage Rank 的页面口径 | 只读兼容测试 |
| `js/config-relation-observer.js` | 表单字段、校验、拓扑和修复行为的原始证据 | 人工审查与上游验证 |
| `js/config-relation-capacity.js` | 页面理论容量公式的原始证据 | 人工审查与上游验证 |
| `config-relation-plane.html` | 左侧训练配置字段和交互布局 | UI 对照，不作为运行依赖 |

当旧仓库不存在时，默认 `npm test` 仍可运行；兼容测试会明确跳过。只有执行
`npm run verify:upstream` 时才要求提供 `TOOL_MATRIX_ROOT` 指向旧仓库或它的只读副本。
