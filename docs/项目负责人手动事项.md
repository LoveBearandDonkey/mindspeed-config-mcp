### 2. 需要把结论提升为 MindSpeed/Megatron 实现一致性时

- [ ] 确认第一版对齐的 MindSpeed 版本；当前候选基线为 `0.12.1`；
- [ ] 提供或允许准备与 `core_v0.12.1` 匹配的 Megatron-LM 工作区和 Commit；

版本实机一致。

### 3. 需要接入 MindSpeed Agent 时

- [ ] 决定采用现有 Plugin/Skill，还是新增 `mindspeed-config-analysis` Skill；
- [ ] 确认安装目标和发布方式；
- [ ] 提供至少一组希望 Agent 演示的真实用户问题及期望回答。

MCP 的五项确定性能力可以先独立完成，不必等待 Agent 集成。

### 4. 需要部署服务器时

- [ ] 提供目标服务器的操作系统、CPU 架构和 Node.js 版本；
- [ ] 提供部署账号与目标目录，并确认是否允许安装依赖；
- [ ] 确认使用本地 `stdio` 还是远程服务方式；
- [ ] 若为远程服务，确认监听地址、端口、TLS、反向代理和访问认证方案；
- [ ] 确认进程托管方式，例如 systemd、Docker 或平台自身的托管服务；
- [ ] 确认日志、监控、升级和回滚要求。

部署信息不要提交真实密码、Token、私钥或生产地址到仓库；通过服务器密钥管理或环境
变量注入。

### 5. 需要真实 NPU 校准或训练验证时

- [ ] 单独授权启动训练；
- [ ] 提供测试机或集群、NPU 配额及连接方式；
- [ ] 提供代码 Commit、CANN/驱动/Python/PyTorch/torch_npu 版本；
- [ ] 提供模型或 checkpoint、数据集、Tokenizer、输出和日志路径；
- [ ] 确认运行步数、超时、停止条件和验收标准。

这属于后续实机闭环，不在第一版 MCP 的默认范围内。
