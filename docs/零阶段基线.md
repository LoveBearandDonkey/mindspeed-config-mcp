# MindSpeed 配置 MCP 零阶段基线

本文记录独立项目开始编码前形成的设计基线，以及范围刷新后的实现状态。

## 第一版范围

第一版按 `集成分析.md` 表中编号覆盖五项纯计算能力：

1. `validate_parallel_config`：并行配置数学约束校验；
2. `compute_rank_topology`：Rank 与 TP/PP/DP/CP/EP 通信组映射；
3. `suggest_config_fixes`：保留指定字段时的最小修复建议；
4. `parse_training_config`：解析 YAML、JSON 或 Shell 并显式报告未识别字段；
5. `estimate_training_capacity`：页面口径的理论容量估算（对应分析表第 6 项）。

这些能力默认满足以下边界：

- 不启动训练；
- 不要求 NPU、CANN、PyTorch 或 torch_npu；
- 不在运行时导入完整 MindSpeed；
- 不读取任意服务器文件路径；
- 页面和未来 MCP Server 共用同一个纯计算核心；
- 每个结论携带规则版本、来源、假设和置信等级。

## 本目录内容

| 文件 | 用途 |
| --- | --- |
| `upstreams.lock.json` | 固定当前三个本地上游仓库的 Commit 和工作区状态 |
| `源码能力映射.md` | 记录五项能力应从哪些真实函数和 MindSpeed 规则中抽取 |
| `packages/contracts/training-config-v1.schema.json` | 页面到纯计算核心的统一输入草案 |
| `packages/contracts/tool-result-v1.schema.json` | 五项工具共享的结果信封 |
| `验收矩阵.md` | 抽取前后必须保持一致的代表性验收场景 |
| `tools/verify-upstream-baseline.cjs` | 按正确加载顺序只读验证现有页面纯计算入口 |
